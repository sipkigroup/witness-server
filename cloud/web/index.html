Deus Witness™

For developers of unattended agents

Face ID, fingerprint or security key for your AI agent's risky actions. And a hard budget.

For agents that run with nobody watching: cron, claude -p, CI. A Claude Code hook sends each shell, file, web and MCP call to a hosted witness before it runs. What the rules you signed once with your passkey allow runs, what they forbid is refused, anything else waits for your approval, and no answer means refused. Free for one person, no card.

Try in Claude Code (about 2 minutes, no sign-up form)

Needs Claude Code 2.1.295+ and uv (curl -LsSf https://astral.sh/uv/install.sh | sh); macOS, Linux, WSL.

/plugin marketplace add sipkigroup/witness
/plugin install deus-witness@sipkigroup
/deus-witness:try

Then ask Claude anything; the first call that needs you waits on the page. “3 userConfig options not yet set” is expected: /plugin install opens a settings panel whose options can stay unset. If asked, run /reload-plugins.

Makes a quick start account and opens a browser page. Two passkey prompts (create the passkey, sign the rules), then the call that is waiting; if nobody touches the page within 90 s, that call is refused. Without the plugin, uvx --from deus-witness deus-witness try only creates the account; add the hook yourself (quickstart). An account nobody claims with a passkey and whose hook never calls is erased after 7 days.

Why not just Claude Code's own permissions?

A permissions.deny rule matches the command text and can only block; in claude -p nobody can answer a permission prompt, so calls that need one are refused. Deus Witness adds your passkey approval of the exact call, from any device, and a signed receipt someone else can verify without trusting us. It is not a sandbox: run your agent inside one too (OpenShell, sandbox-runtime, a container). Guides: hooks vs permissions.deny, permissions.deny not working?, --dangerously-skip-permissions.

Or set it up by hand for any MCP client:

claude mcp add witnessed --env DEUS_WITNESS_KEY=dwk_YOUR_KEY --env DEUS_WITNESS_URL=https://witness.sipkigroup.com -- deus-witness-mcp -- YOUR-MCP-SERVER-COMMAND

One line for any MCP client (Claude Code shown). For Claude Code's built-in tools (Bash, Edit, Write and also Read, Grep, Glob, web and MCP tools) there is a PreToolUse hook that blocks the call when a key is set and the witness cannot be reached. Without a key it is fail-open (it warns and lets calls pass) unless strict is on. See the quickstart, PreToolUse hook examples and human approval for MCP tool calls.

Unattended runs: cron, claude -p, CI

A night job has nobody at the terminal to stop a bad call. With the Claude Code hook every tool call of the run is checked against the mandate you signed: what it covers runs, what it forbids is refused, and what needs you waits for your passkey. The link comes to Telegram, Slack, e-mail or a push on your phone.

pip install deus-witness
deus-witness-hook --doctor /path/to/project   # must say: OK: fail-closed
claude -p "Run the tests, fix what fails. Do not push." --output-format json

Before that: an agent with the claude-code preset, its mandate, and our settings.unattended.json as the project's .claude/settings.json (pip needs Python 3.10+ in a venv outside the project). If the witness cannot be reached, the call is blocked, not run. Background: headless mode (claude -p): permissions and approvals.

If nobody approves in time, the call does not run. The hook waits up to 10 minutes. Approve within that time and the call runs in the same run. Otherwise it is refused and that step is not done (through MCP the agent gets Action NOT executed). The agent may go on with other work or stop; our cron and CI templates then exit with code 3, so cron mail or a red job tells you.

Nothing re-runs the job for you. Deus Witness does not restart your agent, and the templates do not retry. An approval you give later still counts until the request expires, 15 minutes after it was asked: if you re-run the job by then and it makes exactly the same call, that call passes once (for Claude Code's shell this needs the hook deus-witness 0.2.33 or newer: older hooks send Claude Code's free-text description of the command, which differs on every try). Later, or with different arguments, it needs a new approval.

For a job on a schedule, approve once for the next runs. When you approve, open “More options” and tick “Also approve this exact call for this agent's later runs”: the same call with exactly the same arguments then runs in the next runs without asking you, up to 1, 3 or 10 more times within 1, 24 or 72 hours. One passkey prompt signs it. The first use is reported to your channels at once; further uses are reported as one summary at most every 10 minutes (the number of calls, no arguments). Any other call is still asked, and you revoke it in one click on the Permissions page. For a shell command it approves the command line, not the script it runs: it ends as soon as the agent writes a script or source file that command runs. Needs the hook deus-witness 0.2.33 or newer for Claude Code's shell.

A budget that adds up

The budget counts across all actions in the mandate window, not per call, so ten small purchases cannot add up to more than one big one. Over budget means denied, with the reason recorded.

It caps actions that go through the witness. It does not cap your model's own token spend.

Your approval, bound to one action

A held action waits for your passkey. The approval covers that one action and cannot be replayed for another. Only if you tick “also for later runs” does it also cover the same call, with exactly the same arguments, in the agent's next runs, up to the number of times and the hours you chose. You get a push notification on your phone; if it does not arrive, the request is still on your approvals page.

Rules decide, not a model: the verdict comes from your signed mandate.

For security teams

A black box for your agents: a tamper-evident audit log

When an agent sends mail, moves money, deletes or publishes, the usual record is the log of the party being judged. Deus Witness keeps a separate, tamper-evident audit log: a log that cannot be quietly changed afterwards, with timestamps. It holds proof that the agent stayed within a signed mandate, or exactly where it did not.

  • A tamper-evident, hash-chained log that cannot be quietly rewritten later, timestamped (see "How it is verified").
  • A human-signed mandate. What the agent was allowed to do, signed with a named person's passkey.
  • A decision for every action that goes through the gateway. Allowed, denied or held, with a reason code, in a signed receipt.
  • An evidence pack you check offline with open-source verifiers (Apache-2.0): the JS and Swift ones are separate implementations (by the same author as the service); the Python checker in pip install deus-witness comes from the same source as the service, so it is not independent.

How it works

  1. Sign in with a passkey
    No password. A laptop, or a phone through a QR code.
  2. Create an agent
    You get an API key, shown once, and the one-line config.
  3. Sign a mandate
    A plain form. Your browser shows exactly what is signed.
  4. Watch and decide
    Each action is allowed, denied or held for you. Download an evidence pack and verify it offline.

Honest limits

Deus Witness is a tool that helps you set limits and keeps a record. It does not guarantee that an agent will not cause loss, damage, data leakage, unauthorized payments, deletion or publication. You remain responsible for your agents and what they can reach.

  • We only see what is routed through us. Shell commands, built-in tools, direct network calls and a misconfigured proxy are not seen and leave no receipt, unless you wire in the hook and deny the rest. A "coverage level" shown by the tool is the operator's own statement, not something we verify.
  • A mandate that allows an action will allow it. Decisions are only as good as the mandate, the tool map and the patterns you configure.
  • Data checks are literal patterns. Rephrased, encoded or split content gets past them. The recipient rules are the stronger line.
  • Approval is not free of friction, and notifications can fail. In our own measurement on a simulated workload, about 15 of every 100 actions still needed a passkey prompt (we had aimed for 2 or fewer). Pushes can be late or not delivered.
  • Your passkey device does not display the mandate or the action. You read them on this page, so you trust its scripts. They are plain files with no build step (the server only writes the site's build into their addresses, ?v=, so an older cached copy is never mixed in); hashes of the files as served are listed below. On the approval screen, invisible and direction-changing characters are shown as <U+202E> and mixed-script look-alikes are flagged, but a clean result does not prove an address is genuine.
  • The budget covers actions taken through tools, not your model's token spend.
  • A timestamp proves a hash existed by a time, not that the action was lawful, correct or authorized by a person. An evidence pack is a technical record, not legal advice, an audit report or a qualified timestamp (eIDAS).
  • In this preview the witness operator is us (Sipki LLC, New York): one hosted server on an ordinary VPS, not in a TEE, and we register your key on our own site (no device attestation). The receipt format, clients and verifiers are Apache-2.0 on GitHub; the server code is AGPL-3.0 (witness-server). Early 0.x, beta. The specification and implementations have not been reviewed by outside parties.
  • The demo attacks are scripted. They show that the gateway enforces the mandate, not how often real agents are fooled.

How it is verified

Each hour the ledger checkpoint is timestamped (OpenTimestamps) and anchored in a public blockchain under the hood, so entries up to the last public anchor cannot be rewritten without detection; newer entries rely on the server until the next anchor is confirmed in the public blockchain (stamped hourly, confirmed a few hours later); only a 32-byte hash leaves the service. The anchor time means "not later than block N", accurate to hours, not seconds. Packs verify offline with open-source verifiers. The format is a draft specification (draft-deus-aar in the repository), not yet submitted to the IETF and not a standard.

Page script hashes

SHA-256 of the files that encode and sign your mandate. Compare them with shasum -a 256 on what your browser loads.
