    How to turn on the strict sandbox (macOS)

    A test runner runs code the agent may have written. Without the sandbox below every runner needs your approval, whatever you choose here. With it, the operating system keeps the runner from reading your keys and from reaching the network. The keys are Claude Code's own, from code.claude.com/docs/en/sandboxing. Set three places:

    1. Your user settings ~/.claude/settings.json (or managed settings) lock the network. Claude Code ignores this key in a project's settings, and the hook cannot see --settings:

    { "sandbox": { "network": { "strictAllowlist": true } } }

    2. The project's .claude/settings.json:

    {
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "filesystem": { "denyRead": ["~/", "./.env"], "allowRead": ["."] }
  }
}

    3. The shell you start Claude Code from: export CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1. A settings env block does not turn the scrub on.

    "With the retry disabled, Claude Code ignores the dangerouslyDisableSandbox parameter." Without strictAllowlist, bypassPermissions mode lets a sandboxed command reach any host. Accepted permission modes: default, acceptEdits and bypassPermissions (that includes --dangerously-skip-permissions). In auto, plan and dontAsk the runner is asked. Keep sandbox.excludedCommands and sandbox.network.allowedDomains empty and add no Unix sockets. Any of these, a .env file of the project left readable, or Linux/Windows makes the sandbox "not strict", and the runner is asked. The scrub also removes DEUS_WITNESS_KEY from the hook's environment, so give the hook its key with the key file that deus-witness try saves. A mandate signed before this option keeps asking until you sign a new one with it.

    HTTP requests (OpenShell sandbox)

    A rule names an endpoint: METHOD host[:port]/path. * is one path segment, a final ** is one or more; no port means 443. A rule allows that endpoint with any query and body; requests carrying secrets or personal data are refused anyway, and every other request is asked or refused, as you choose below.
